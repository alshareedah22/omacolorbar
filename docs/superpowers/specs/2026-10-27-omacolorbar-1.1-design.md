# OmaColorBar 1.1.0: color tray app icons, indicators and weather

Date: 2026-10-27 · Status: design approved in chat, awaiting spec review
Builds on: `2026-10-27-omacolorbar-design.md` (1.0.0). Everything there still holds
unless this document says otherwise.

## Goal

Extend OmaColorBar to three more of Omarchy's bar widgets:

- `omarchy.tray`: every tray app whose installed app icon can be found shows that
  app's own full-color icon instead of its (usually monochrome) tray image.
- `omarchy.indicators`: the six indicators get color icons when on and gray icons
  when off.
- `omarchy.weather`: the condition glyph becomes a color drawing; the temperature
  text stays.

Clicks, menus, pinning, tooltips and popups stay Omarchy's own, as in 1.0.0.

## Constraints (in addition to 1.0.0's)

- No logo is redrawn for tray apps: only the app's own installed icon (resolved from
  its `.desktop` entry through the icon theme) is shown.
- Indicators: color when the mode is on, gray when off (user decision).
- Tray scope: every tray app with a findable app icon (user decision); no list.
- The tray adapter is built only after a spike proves it works; if it does not, tray
  moves to a later release and 1.1.0 ships indicators and weather.

## Approach

One plugin, as in 1.0.0. The `icon` setting gains `omarchy.tray`,
`omarchy.indicators` and `omarchy.weather`. Hosting is unchanged (registry from the
service entry point, the real widget created in a `Loader`, `bar`/`moduleName`/
`settings` injected). What differs per widget is how its icons are swapped, so
`Panel.qml` dispatches to one of three adapters:

| Adapter | Used for | How it swaps |
|---|---|---|
| button (1.0.0) | the ten 1.0.0 widgets and weather | `BarIconButton.iconComponent` from the button's glyph; label text kept |
| indicator | `omarchy.indicators` | every `BarIndicator` inside the hosted widget gets the menu-style overlay: `labelVisible = false` and an `Image` chosen from its glyph and `effectiveActive` |
| tray | `omarchy.tray` | every tray icon item inside the hosted tray gets its `Image.source` replaced by the matched app icon |

Adapters live in `Panel.qml` unless it grows past about 450 lines; then the
indicator and tray adapters move to `IndicatorAdapter.qml` and `TrayAdapter.qml`
(each an `Item` given the hosted item and returning nothing; they only attach).

## Weather

The weather button's text is the condition glyph plus the temperature
(`panels/weather/BarWidget.qml`: `text: panelLoader.item.label`). `Icons.drawingFor`
handles it like power: last private-use glyph = drawing, rest = label.

| Glyph | Condition (Omarchy `iconForCode`) | SVG name |
|---|---|---|
| `e30d` / `e32b` | clear, day / night | `weather-clear-day` / `weather-clear-night` |
| `e302` / `e32e` | partly cloudy, day / night | `weather-partly-day` / `weather-partly-night` |
| `e33d` | cloudy, overcast, default | `weather-cloudy` |
| `e313` / `e346` | fog, day / night | `weather-fog-day` / `weather-fog-night` |
| `e308` / `e333` | light showers, day / night | `weather-showers-day` / `weather-showers-night` |
| `e318` | rain | `weather-rain` |
| `e30a` / `e327` | light snow, day / night | `weather-snow-day` / `weather-snow-night` |
| `e31a` | heavy snow | `weather-heavy-snow` |
| `e3ad` | sleet, freezing rain | `weather-sleet` |
| `e31d` | thunder | `weather-thunder` |

Palette: sun `#f59e0b`→`#fde047`; moon `#c4b5fd`→`#e0e7ff`; cloud `#94a3b8`→`#e2e8f0`;
rain drops `#38bdf8`; snow `#ffffff`; lightning `#facc15`. Fog and night glyphs
`e313`/`e346` are written as ``/`` escapes in Omarchy's source, so the
installed-source test must decode `\uXXXX` escapes.

## Indicators

`omarchy.indicators` hosts `bar/indicators/*.qml`, each a `BarIndicator` (a
`WidgetButton` with `activeText`, `inactiveText`, `effectiveActive`). The adapter
finds every item with `activeText`, `inactiveText` and `effectiveActive`, sets
`labelVisible = false`, and adds an `Image` overlay sized `Style.bar.iconCanvas`,
centered, whose source is `Icons.indicatorDrawing(glyph, active)`:

| Indicator | Glyph(s) | SVG names (on / off) | Hues |
|---|---|---|---|
| Stay awake | `f0176` | `ind-stayawake` / `ind-stayawake-off` | `#d97706`→`#fbbf24` |
| Do Not Disturb | `f009b` | `ind-dnd` / `ind-dnd-off` | `#ef4444`→`#f97316` |
| Night light | `f050e` | `ind-nightlight` / `ind-nightlight-off` | `#f97316`→`#fde68a` |
| Screen recording | `f0ec2` | `ind-recording` / `ind-recording-off` | `#dc2626`→`#f87171` |
| Dictation | `f051f` (on), `f036c` (off glyph) | `ind-dictation` / `ind-dictation-off` | `#0ea5e9`→`#a78bfa` |
| Reminder | `f088c` | `ind-reminder` / `ind-reminder-off` | `#10b981`→`#6ee7b7` |

The `-off` variants are the same shapes with the gray pair `#6b7280`→`#9ca3af`,
generated by `tools/make_icons.py` from the same shape function so they never drift.
The glyph shown is `effectiveActive ? activeText : inactiveText`; the drawing is
picked from that glyph and `effectiveActive`. Unknown glyph → overlay hidden and
`labelVisible` restored (Omarchy's glyph shows). The indicators widget's own
settings (`items`, `alwaysShow`) live in `plugins[]` like any hosted widget's.

## Tray

Each tray icon in `plugins/bar/widgets/Tray.qml` is a `TrayIcon` (an `Item` with
`required property var icon` and a child `Image` whose `source` is the item's
`image://` URL); its delegate has `modelData` with `id`, `title`, `tooltipTitle`.

Matching (pure function in `Apps.js`, tested in Node):
`matchApp(trayItem: {id, title, tooltipTitle}, apps: [{name, icon, wmClass, desktopId}]) → icon name | ""`.
Normalise strings (lowercase, drop non-alphanumerics), then match in this order:
1. `wmClass` equals or is contained in the tray `id`;
2. the desktop id (file name without `.desktop`, last dot segment too) is contained
   in the tray `id` or `title`;
3. the app `name` equals the tray `title` or `tooltipTitle`, or is the leading word
   of the tray `id` (e.g. `Claude_status_icon_1` → `claude`).
First match wins; no match → `""`.

App list: read once at start and on change from `~/.local/share/applications` and
`/usr/share/applications` (`Name=`, `Icon=`, `StartupWMClass=`, `NoDisplay` ignored)
with Quickshell's `DesktopEntries` if it exposes those fields, otherwise by reading
the files with `FileView`/`Process` (`grep`), decided in the spike. Icon resolution:
`Quickshell.iconPath(iconName, true)`; an absolute `Icon=` path is used as is. If the
path is empty or the `Image` reports `Error`, the original `source` is restored.

The spike (first plan task) must prove, on the live bar with Claude running: the
hosted tray shows its items, a `TrayIcon`'s `Image.source` can be re-bound to
Claude's `claude-desktop` icon, the click and the right-click menu still work, and
pin/hide in the tray's manage panel still work. If any fails, tray is dropped from
1.1.0 and the plan continues with indicators and weather.

## colorbar

`SUPPORTED` gains `omarchy.tray`, `omarchy.indicators`, `omarchy.weather` (same
order as the manifest). `swap` on an already swapped bar with its backup present
behaves as 1.0.0: it refuses without `--force`; with `--force` it keeps the original
backup and swaps the remaining built-ins. README tells existing users to run
`colorbar swap --force` after updating.

## Failure behavior (additions)

| Situation | Behavior |
|---|---|
| Tray app with no matching `.desktop` | keeps its own tray image |
| Matched icon path empty or image fails | original tray image restored |
| Indicator or weather glyph without a drawing | Omarchy's original glyph |
| Tray spike fails | tray not shipped in 1.1.0; documented in README |

## Testing

- Node: weather glyphs (15) and indicator glyphs (on/off, 7 glyphs) map to drawings;
  the installed-source scan covers `panels/weather/Model.js` `iconForCode` (decoding
  `\uXXXX`) and every `bar/indicators/*.qml` `activeText`/`inactiveText`;
  `matchApp` on samples (Claude `Claude_status_icon_1` → `claude-desktop`, ChatGPT,
  Steam `steam`, a case-only difference, a no-match); SVG safety for the new files;
  `SUPPORTED` equals the manifest options.
- Python: `colorbar` swaps the three new ids; `--force` keeps the original backup.
- Live: Claude's tray icon in color, its click and menu work; ChatGPT's while running;
  stay awake toggled on (color) and off (gray when revealed); weather shows its
  condition icon and temperature; no `[omacolorbar]` warnings; screenshots read.
